API reference

Tez speaks TypeSafe's /v1/systemone wire format, so a client written for Jev's wire format, JevBench's own runner included, can point its base URL at a Tez server. Everything Tez adds lives in optional fields that strict clients ignore.

Base URL and authentication

Default address: http://127.0.0.1:8787. Without --api-key any Authorization: Bearer <token> is accepted and none is required. With --api-key, every endpoint except /healthz needs Authorization: Bearer <key> or an x-api-key header. CORS is open by default (--no-cors turns it off), and preflights answer Access-Control-Allow-Private-Network: true, so a web page, such as this site's playground, can call a server on your machine.

MethodPathPurpose
POST/v1/systemoneDecide: one state, many typed questions (Jev-compatible)
GET/v1/modelsList model aliases (Jev-compatible)
GET/healthzLiveness, backend and readout status
GET/v1/schemasTez: schemas loaded from --schemas
GET/v1/schemas/{name}Tez: one schema (questions, probe status, calibration)
POST/v1/feedbackTez: record a correct label for a past decision (feeds tez fit)

POST /v1/systemone

Decide one state against many typed questions. The request body:

FieldTypeDescription
statestring, object, arrayRequired. The input to decide on. Objects and arrays are serialised as JSON.
questionsobjectMap of question id to question. Required unless schema names a loaded schema, whose questions are then used.
questions.{id}.typestringnoul (yes/no), choice (2 to 255 options) or score (2 to 10 ordered levels).
questions.{id}.instructionsstring, object, arrayRequired. What to decide.
questions.{id}.criteriaobject or arraychoice: label to description or null. score: a list of level descriptions, level i = index i. noul: optional {"true": …, "false": …}.
modelstringAny string; tez-latest is the default alias.
schemastringTez. Name of a loaded schema. Questions with the same id use that schema's trained probe and calibration.
tez.readoutstringTez. auto (default: the probe when one is trained and current for the question, otherwise letters), letters or probe.
tez.abstainbooleanTez. Adds an implicit __none__ option ("none of these fits") to every choice question. Default false.
tez.gate.alphanumberTez. Target error rate among acted decisions, between 0 and 1. Each answer then gets act or escalate; see The gate.

The Tez extensions together:

json · request extensions
{
  "schema": "support-triage",
  "tez": {
    "readout": "auto",
    "abstain": false,
    "gate": {"alpha": 0.05}
  }
}

FieldTypeDescription
modelstringtez-<version> (<model>, <readouts used>).
answers.{id}objectOne answer per question, in Jev's shapes (below).
usage.input_tokensintegerPrompt tokens across all questions, cached prefix included.
usage.output_tokensintegerAlways 0: nothing is generated.

Answer shapes

The three answer shapes are exactly Jev's:

TypeFieldsMeaning
noulnoulP(yes). No confidence: Jev's noul answers carry none.
choicechoice, probabilities, confidenceThe argmax label, a probability per label (they sum to 1), and confidence = (k·pmax − 1)/(k − 1) for k options: 0 when uniform, 1 when certain.
scorescore, legend, probabilities, confidenceThe expected level Σ i·pi, the level descriptions keyed by level string, a probability per level string, and confidence as for choice.

With tez.abstain, a choice answer can be __none__, with its own probability.

The tez block

latency_ms, and per question the readout used, a decision when a gate applies, and p_correct with calibration_id when a fitted calibration exists.

  • The gate never acts without evidence: act always comes with p_correct and calibration_id. A question with no usable fitted calibration, and any __none__ answer, gets escalate whenever a gate is requested.
  • tez.gate: null or false turns a schema's default gate off; tez.gate: {} uses the schema's default alpha.
  • Thresholds are precomputed for alpha 0.01, 0.02, 0.05, 0.1, 0.15, 0.2, 0.25, 0.3 and the schema's default; any other alpha uses the largest precomputed value at or below it.
  • tez.readout: "probe" is strict: the request fails with 422 if a requested question has no usable probe. auto falls back to letters question by question.
  • A fit is used only while the question's prompt (instructions, options, few-shot examples, template) and the model still match what tez fit saw. Otherwise the question falls back to uncalibrated letters and GET /v1/schemas/{name} marks it stale.

Errors

The same codes as Jev, with one body shape: {"error": {"type": "…", "message": "…"}}. Messages name the offending field.

StatustypeWhen
401unauthorizedThe server runs with --api-key and the request has no valid key.
404not_foundUnknown route, or GET /v1/schemas/{name} for a schema that is not loaded.
405method_not_allowedWrong method for a route.
422invalid_requestThe request does not match the contract, tez.readout: "probe" for a question without a usable probe, or a prompt longer than the model's context (with llama.cpp's message).
503backend_unavailableThe model server is unreachable, still loading or failed.
json · 422 response
{"error": {"type": "invalid_request", "message": "questions.q.type must be one of noul, choice, score; got 'multi'"}}

Other endpoints

GET /v1/models

json · response
{"models": [{"name": "tez-latest", "description": "Tez local decision engine (gemma-4-12b-q8_0, letters)", "release_date": "2026-09-24"}]}

GET /healthz

json · response
{"status": "ok", "version": "0.1.0", "backend": "http://127.0.0.1:8091", "template": "gemma4", "backend_status": "ok",
 "model": "gemma-4-12b-q8_0", "embed_backend": null, "schemas": ["support-triage"], "probes": {"support-triage": ["topic"]}}

status is degraded when the backend is unreachable (backend_status: "unreachable"). With a separate embedding backend, embed_template and embed_backend_status are added. /healthz needs no key.

GET /v1/schemas and /v1/schemas/{name}

json · GET /v1/schemas
{"schemas": [{"name": "support-triage", "description": "...", "questions": {"topic": "choice", "is_urgent": "noul"},
              "calibration_id": "support-triage@2026-09-24", "probes": ["topic"]}]}

One schema returns its questions in wire form plus calibration_id, probes (per question: probe is ready, stale or none, with letters_calibrated, n_labels and a note), calibration and manifest.

POST /v1/feedback

json · request
{"schema": "support-triage", "question": "topic", "state": "Help! My payouts have been failing for 3 days.", "label": "billing"}

Records the correct label for a past decision. Tez appends the row to <data-dir>/feedback/<schema>.jsonl (the data dir defaults to <schemas>/.tez) and answers {"ok": true, "schema": …, "question": …, "label": …}. tez fit trains from these rows plus any labelled file.
