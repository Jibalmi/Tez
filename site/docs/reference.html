Reference

Every command and flag of the tez CLI, the environment variables, the Python API, fixes for the problems people hit, and short answers to common questions.

CLI reference

tez has nine commands; tez <command> --help prints the same options, and python -m tez works too. tez --version prints the version. Most settings can also come from environment variables; a flag on the command line wins. The MCP server is a separate program, tez-mcp (MCP server).

usage
tez serve | decide | plan | fit | suggest | eval | doctor | presets | truncate

Backend options

Shared by serve, decide, plan, fit, suggest, eval and doctor; doctor has no embedding options.

--backend URLdefault http://127.0.0.1:8080, or TEZ_BACKEND
llama-server URL, inproc:PATH.gguf to load the model inside Tez (Run the model inside Tez), or fake for the offline demo backend.
--template {gemma4,qwen3}default gemma4, or TEZ_TEMPLATE
Prompt template of the model behind --backend.
--embed-backend URLdefault: --backend, or TEZ_EMBED_BACKEND
Separate llama-server for probe features, started with --embeddings --pooling last.
--embed-template {gemma4,qwen3}default: --template
Prompt template of the embedding model.
--no-cache-prompt
Switch llama.cpp prompt caching off for every backend (hybrid Qwen3.5 GGUFs crash b11100 on partial prefix reuse).
--model-name NAMEdefault: read from the server
Model name used in responses and calibration, and to choose the default temperature.
--n-probs Ndefault 200
Next-token log-probabilities a letters readout asks for; an option letter outside them gets the floor probability (Letters).
--default-temperature auto|off|Tdefault auto, or TEZ_DEFAULT_TEMPERATURE
Temperature for letters answers that no fit calibrates: auto uses the values measured for Gemma 4 12B Q8_0 with gemma4 and 1 for any other model, off is 1, or a number (Default temperature).
--llama-lib DIRdefault TEZ_LLAMA_LIB, then next to llama-server on PATH
In process: the directory of llama.cpp's library (llama.dll, libllama.so or libllama.dylib) from a llama.cpp release; tested with b11100.
--n-ctx Ndefault 4096, or TEZ_N_CTX
In process: the KV cache in tokens, shared by the questions of a request.
--n-batch Ndefault --n-ctx, or TEZ_N_BATCH
In process: the most tokens per decode.
--n-gpu-layers Ndefault -1 (all), or TEZ_N_GPU_LAYERS
In process: layers on the GPU; 0 runs on the CPU.

A request past any of the four limits gets 413 payload_too_large, and 0 switches a limit off (Limits).

tez decide

Decide one state and print the wire-format JSON, or decide a file of states as one batch. Give --schema or --preset, --questions, or a schema and --questions; and give the state once: as TEXT, --state, --state-file or --states-file.

TEXT
The state as text, as the first argument.
--schema FILE
Schema YAML file; its fitted probes and calibration are used.
--preset NAME
A built-in preset schema (tez presets lists them), instead of --schema.
--questions FILE
JSON file with Jev questions ({id: {type, instructions, criteria}}).
--state TEXT
The state as text.
--state-file FILE
File with the state (- reads stdin; *.json is parsed as JSON).
--states-file FILE
JSONL file of states (rows with a state, JSON values or text lines), decided as one batch: one result line per row, in order (Batch decisions).
--out FILE
With --states-file: write the result lines here instead of stdout.
--readout {auto,letters,probe}default auto
Which readout to use.
--abstain
Add the implicit __none__ option to choice questions.
--alpha ALPHA
Gate: target error rate among acted decisions.
--compact
One-line JSON.
--layout {auto,question_first,state_first}default: the schema's, else auto
Prompt layout.
--hook MODULE:OBJECTrepeatable
Load a hook: a class is instantiated, a hook instance is used as it is, a factory is called. Hooks run in the order given. The module must be importable; for one in the working directory, run with PYTHONPATH=. (Hooks on tez serve).
--decision-log PATH
Append every decision to this JSONL file, as rows tez fit reads once their labels are filled in.
--hook-errors {raise,log}default raise
A hook that raises fails the decision (raise) or is logged and skipped (log).

With --states-file, a state that fails gets an error line and the others are still decided; a summary goes to stderr, and the exit status is 1 only when every state failed.

bash
tez decide --backend http://127.0.0.1:8091 --template gemma4 \
  --schema schemas/support-triage.yaml --state "Help! My payouts have been failing for 3 days."
tez decide "Help! My payouts have been failing for 3 days." --preset support-triage --compact \
  --backend http://127.0.0.1:8091 --template gemma4

tez plan

Show what a request would do without calling the model: per question the readout, the layout, the fit's status, the backend calls and an estimate of the prompt tokens (characters / 4), and how many of them the prompt cache would reuse. The state is optional; without it, the estimate leaves it out. --json prints the POST /v1/plan response (Plan).

TEXT, --state TEXT, --state-file FILE
The state, as for tez decide; optional.
--schema FILE, --preset NAME, --questions FILE
The questions, as for tez decide; a schema's fits are shown.
--readout, --abstain, --alpha, --layout
As for tez decide.
--json
Print the plan as JSON.
bash
tez plan "My invoice is wrong and I need it fixed today." --preset support-triage
tez plan --preset support-triage --json > plan.json    # no state: the estimate leaves it out

tez doctor

Check a llama-server for what Tez needs, and print a fix for anything that is off. It sends a handful of tiny prompts and changes nothing on the server; the exit status is 1 when a check fails.

CheckWhat it looks at
healthGET /health answers ok (503 while the model loads)
modelGET /props: the model file, build, context size and slots
templateThe model's chat template matches --template
n_probs/completion returns the top --n-probs log-probabilities, with the option letters among them
cacheThe same prompt twice: the second is served from the prompt cache
prefixTwo questions about one state, read state first: the second reuses the state (Gemma needs --swa-full)
embeddings/embedding works (fitted probes need --embeddings --pooling last, or a separate --embed-backend)
slotsOne slot (-np 1), so consecutive questions share one cache
cache-ramllama.cpp's host-memory prompt cache, which the Docker Compose files switch off (Docker)
--backend, --template, --no-cache-prompt, --model-name, --n-probs
As in Backend options.
--timeout SECONDSdefault 60
Seconds per request.
--json
Print the checks as JSON.

With --backend inproc:PATH.gguf the doctor loads the model in its own process (the GPU needs room for it) and checks library (llama.cpp's library was found, and its build), gpu (a GPU backend loaded and holds the layers), model, memory (a hybrid Qwen3.5 model reuses a prefix only by sequence copies), template, letters (the option letters hold most of the next-token probability), batch (a batched read agrees with reading the questions one by one), embeddings and process. With --backend fake it reports that there is nothing to check and exits 0.

bash
tez doctor --backend http://127.0.0.1:8091 --template gemma4

tez presets

List the ten built-in preset schemas with their questions, or print one as YAML to copy into your schema directory, edit and fit (Presets).

bash
export TEZ_BACKEND=http://127.0.0.1:8091 TEZ_TEMPLATE=gemma4 TEZ_SCHEMAS=schemas TEZ_PRESETS=1
tez serve --log-level warning    # a flag wins over the environment

Python API

The server is a thin layer over the Tez class, and the same engine runs in your own process. decide returns the wire-format response as a dict.

python
from tez import Tez

tez = Tez(backend="http://127.0.0.1:8091", template="gemma4")
res = tez.decide(
    "Help! My payouts have been failing for 3 days.",
    questions={
        "topic": {
            "type": "choice",
            "instructions": "What is the message about?",
            "criteria": {"billing": "Payments, payouts, invoices", "technical": "Something is broken", "sales": None},
        },
    },
)
print(res["answers"]["topic"])      # the same shape as the HTTP response

# with schemas, probes and a gate
tez = Tez(backend="http://127.0.0.1:8091", template="gemma4",
          embed_backend="http://127.0.0.1:8092", embed_template="qwen3", schemas="schemas")
res = tez.decide("I can't log in since this morning.", schema="support-triage", alpha=0.05)
print(res["tez"]["questions"])      # readout, act or escalate, p_correct, calibration_id

Errors are TezError subclasses carrying the HTTP status and type: InvalidRequest and BackendRequestError (422) and BackendUnavailable (503), exported by tez, and NotFound (404), Unauthorized (401), Forbidden (403), PayloadTooLarge (413) and InternalError (500) in tez.errors. extract raises EscalationRequired, a plain exception, when a gated field escalates.

The package also exports load_schema, load_schemas, Schema, Question, parse_question, Backend, LlamaCppBackend and FakeBackend; the hooks (BaseHook, DecisionContext, DecisionLog, Redact, Cache, Metrics, OTelHook, set_default_hooks, default_hooks); and EscalationRequired and ExtractResult. Other modules:

  • tez.fit: fit, suggest and evaluate, behind the CLI commands of the same names (needs the fit extra).
  • tez.server.create_app(tez, api_key=None, cors=True, limits=None, cors_origins=None): the FastAPI application, to mount in your own server. It applies tez serve's limits and allowed origins unless you pass others.
  • tez.config.Limits(max_body_bytes, max_questions, max_state_chars, max_batch): request limits for handle, handle_batch, execute, plan and create_app. The defaults are tez serve's; Limits.unlimited() has none. The methods apply no limits unless you pass them.
  • tez.state.email_state(subject, body, sender=None, clean=True, **extra) and clean_email(body, max_chars=3000): an email as a state, with quoted history, signatures, device footers and confidentiality disclaimers removed (English, Portuguese and Spanish mail clients).
  • tez.integrations.remote.RemoteTez: the same methods over HTTP (Python over HTTP); tez.integrations.langchain: LangChain tools and nodes (LangChain and LangGraph).

Troubleshooting

In process: llama.cpp's library is not found

--backend inproc: needs the library from a llama.cpp release: unpack the release archive for your platform and GPU and point --llama-lib (or TEZ_LLAMA_LIB) at the directory that holds llama.dll, libllama.so or libllama.dylib. Without either, Tez looks next to llama-server on PATH. tez doctor --backend inproc:PATH.gguf names what it found.

In process: no GPU backend loads

On Windows, ggml-cuda.dll fails to load (error 126) when the CUDA runtime DLLs are not beside it, and llama.cpp would carry on on the CPU without a word. Tez stops with the reason instead: unpack the release's CUDA runtime (cudart) archive into the same directory as llama.dll. --n-gpu-layers 0 runs on the CPU on purpose.

llama-server crashes on a Qwen3.5 model

Partial reuse of a cached prompt crashes llama.cpp b11100 with hybrid Qwen3.5 GGUFs. Tez switches caching off for backends whose model name matches Qwen3.5; if your file is named otherwise, pass --no-cache-prompt (or --model-name), and send "cache_prompt": false yourself when you call llama-server directly.

Every request re-reads the whole prompt

Start Gemma with --swa-full. Without it the sliding-window cache cannot be rolled back to the shared prefix and each call pays for the full prompt: 205 ms instead of 30 ms per streamed word in the voice loop. Check timings.prompt_n in a /completion response, or run tez doctor.

No token probabilities from a depth-pruned model

A cut model sometimes puts end-of-sequence first when read greedily, and /completion then returns no completion_probabilities. Tez repeats the request with "ignore_eos": true; do the same when you call llama-server yourself.

503 backend_unavailable

Tez could not reach the model server, or the server is still loading (llama-server answers 503 while it loads, and Tez retries twice). GET /healthz reports backend_status: "unreachable" when nothing answers at --backend.

A browser page gets 403

tez serve answers browsers only from allowed origins: by default, pages served from this machine (http://127.0.0.1 and http://localhost, any port) and the website's playground (https://jibalmi.github.io). A POST or a CORS preflight from any other origin gets 403 forbidden, and the message lists the allowed origins:

bash
curl -s http://127.0.0.1:8787/v1/systemone -H "Origin: https://example.org" \
  -H "Content-Type: application/json" \
  -d '{"state": "hi", "questions": {"q": {"type": "noul", "instructions": "Is this a greeting?"}}}'
output
{"error": {"type": "forbidden", "message": "origin https://example.org may not request decisions (allowed: http://127.0.0.1:*, http://localhost:*, https://jibalmi.github.io; tez serve --cors-origins)"}}

Start the server with the page's origin in --cors-origins (or TEZ_CORS_ORIGINS). The list replaces the default one, so keep the defaults you still need. https://*.example.com allows every subdomain but not example.com itself, and * allows any origin. Requests without an Origin header, such as curl, SDKs and servers, are not affected; --no-cors refuses every browser.

bash
tez serve --backend http://127.0.0.1:8091 --template gemma4 \
  --cors-origins "http://localhost:*,https://jibalmi.github.io,https://*.example.com"

The playground cannot reach my server

The playground runs in your browser and calls http://127.0.0.1:8787 directly, so the request never leaves your machine. Its origin, https://jibalmi.github.io, is allowed by default: start tez serve without --no-cors, and if you set --cors-origins, keep https://jibalmi.github.io in the list. The first time a public page calls your machine, Chrome asks whether the site may connect to devices on your local network: allow it for this site. Tez answers the browser's private network preflight from an allowed origin with Access-Control-Allow-Private-Network: true. A server started with --api-key rejects requests that do not send the key.

413 payload_too_large

The request passed one of tez serve's limits: a body over 2 MiB, more than 64 questions, a state over 50,000 characters (an object state counts as its JSON), or a batch of more than 64 states. The message names the limit and its flag:

output
{"error": {"type": "payload_too_large", "message": "too many states in one batch: 100 (the limit is 64; tez serve --max-batch)"}}

Split the batch or shorten the state, or raise the limit; 0 switches a limit off. A state nested more than 100 levels deep gets 422 whatever the limits. Tez's methods apply no limits unless you pass limits=, while create_app applies tez serve's.

bash
tez serve --backend http://127.0.0.1:8091 --template gemma4 --max-batch 256

A fitted probe is not used

Fits are tied to the question's prompt, to the model, to the layout and to the --n-probs they were fitted under (fits made before n_probs was recorded count as 200). After editing instructions, options, examples or the template, serving another model, or changing --n-probs, GET /v1/schemas/{name} shows "probe": "stale" with a note, and the question falls back to uncalibrated letters. Run tez fit again. For a change of layout, see the next entry.

A fit is reported stale after a layout change

A schema served with an explicit layout other than the one its fit was made under, set by its layout: key, --layout or TEZ_LAYOUT, reads the fitted questions with uncalibrated letters, and GET /v1/schemas/{name} says why:

bash
curl -s http://127.0.0.1:8787/v1/schemas/support-triage
output, abridged
"layout": null, "served_layout": "state_first",
"probes": {"urgent": {"probe": "stale", "letters_calibrated": false, "n_labels": 40,
                      "note": "fitted under the question_first layout, read with state_first",
                      "layout": "question_first"}}

Serve it under auto, where a fitted question keeps the layout of its fit, or fit again under the layout you serve. A request's own tez.layout works the same way for that request: the question comes back with readout: "letters" and no calibration_id (Fits keep their layout).

bash
tez fit --backend http://127.0.0.1:8091 --template gemma4 \
  --schema schemas/support-triage.yaml --labels labelled.jsonl --layout state_first

Confidences are lower after upgrading

With Gemma 4 12B Q8_0 and the gemma4 template, Tez now reads letters answers that no fit calibrates at a default temperature per question type (6.01 for yes/no, 4.71 for a choice with up to 10 options shown, 2.66 for 11 to 26, 5.18 for a score) instead of at temperature 1. No argmax changes. Yes/no probabilities move towards 0.5 without crossing it, the most probable option of a choice question keeps its place with a lower probability, and a score question's expected level (score) moves towards the middle of the scale while its most probable level stays the same. For an integer level, take the most probable level from probabilities, or run with --default-temperature off.

Each question read at a default shows its temperature in the tez block; fitted questions keep their fitted temperature. A threshold chosen on answers read at temperature 1 needs choosing again, or --default-temperature off (TEZ_DEFAULT_TEMPERATURE=off), which restores the earlier readings (Default temperature).

bash
tez serve --backend http://127.0.0.1:8091 --template gemma4 --default-temperature off

Flat or wrong letters with your own prompts

Gemma 4 is a thinking model: unless the prompt ends with an empty thought channel, its first token is a channel marker, not an option letter. Tez's gemma4 template ends with <|turn>model, <|channel>thought, <channel|>; use the template that matches the model behind --backend.

Stopping llama-server on Windows

taskkill /IM llama-server.exe silently fails under Git Bash, which rewrites /IM as a path. Use PowerShell, Stop-Process -Name llama-server, and check /props before the next run.

FAQ

Is Tez Jev?

No. Tez is not affiliated with TypeSafe AI. It speaks the same wire format, so clients written for Jev work with it, but it is built from the published technique (reading a decision from one forward pass of an open model), and nothing in it was trained on or derived from Jev's outputs; Jev's terms forbid that. Jev was never run for any number on this site: its figures are third-party published and labelled as such.

What hardware do I need?

Every number here comes from one RTX 5080 laptop GPU with 16 GB, running llama.cpp b11100. Gemma 4 12B at Q8_0 is the default for zero-shot letters; the cut Qwen3.5-4B for probes is a 3.53 GB file. Other GPUs, CPUs and Apple silicon can run llama.cpp, but they have not been measured here.

What are the licences?

Tez's code is MIT, except tez/state.py (the email helpers), which is adapted from Laya and is Apache-2.0; THIRD_PARTY_NOTICES.md lists every third-party file. The Gemma 4 and Qwen3.5 weights are Apache-2.0. The SemIf fixtures and prompt code vendored in data/semif/ are MIT. This site's fonts (Geist) are under the SIL Open Font License 1.1 and its icons (Lucide) under the ISC licence; see assets/LICENSES.md.

Does Tez generate text?

No. Each question is one forward pass, and the answer is read from the next-token distribution (letters) or from a hidden state (probe). usage.output_tokens is always 0.

Can I try the API without a model?

tez serve --backend fake runs an offline stand-in that answers from keyword overlap. It is not a model and its answers mean nothing; it exists for wiring clients and tests.

Is Tez on PyPI, a hosted service or the JevBench leaderboard?

None of the three. Install it from GitHub; it runs on your machine and there is no hosted version. Tez has not been submitted to JevBench, so it holds no rank there; the public-tier scores on the benchmarks page use the leaderboard's formulas and are indicative only.
