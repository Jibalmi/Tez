Reference

Every command and flag of the tez CLI, the Python API, fixes for the problems people hit, and short answers to common questions.

CLI reference

tez has six commands; tez <command> --help prints the same options, and python -m tez works too. tez --version prints the version.

usage
tez serve | decide | fit | suggest | eval | truncate

Backend options

Shared by serve, decide, fit, suggest and eval.

--backend URLdefault http://127.0.0.1:8080, or TEZ_BACKEND
llama-server URL, or fake for the offline demo backend.
--template {gemma4,qwen3}default gemma4, or TEZ_TEMPLATE
Prompt template of the model behind --backend.
--embed-backend URLdefault: --backend, or TEZ_EMBED_BACKEND
Separate llama-server for probe features, started with --embeddings --pooling last.
--embed-template {gemma4,qwen3}default: --template
Prompt template of the embedding model.
--no-cache-prompt
Switch llama.cpp prompt caching off for every backend (hybrid Qwen3.5 GGUFs crash b11100 on partial prefix reuse).
--model-name NAMEdefault: read from the server
Model name used in responses and calibration.

tez serve

Run the HTTP server (Jev-compatible /v1/systemone).

--schemas DIR
Directory of *.yaml schemas; trained artefacts live in <dir>/.tez/.
--data-dir DIRdefault <schemas>/.tez
Where POST /v1/feedback writes.
--host HOSTdefault 127.0.0.1
Address to listen on.
--port PORTdefault 8787
Port to listen on.
--api-key KEYdefault TEZ_API_KEY
Require Authorization: Bearer <key>.
--no-cors
Do not send CORS headers (open to every origin by default).
--log-level LEVELdefault info
critical, error, warning, info or debug.

tez decide

Decide one state and print the wire-format JSON. Give --schema, --questions or both, and exactly one of --state and --state-file.

--schema FILE
Schema YAML file; its fitted probes and calibration are used.
--questions FILE
JSON file with Jev questions ({id: {type, instructions, criteria}}).
--state TEXT
The state as text.
--state-file FILE
File with the state (- reads stdin; *.json is parsed as JSON).
--readout {auto,letters,probe}default auto
Which readout to use.
--abstain
Add the implicit __none__ option to choice questions.
--alpha ALPHA
Gate: target error rate among acted decisions.
--compact
One-line JSON.
bash
tez decide --backend http://127.0.0.1:8091 --template gemma4 \
  --schema schemas/support-triage.yaml --state "Help! My payouts have been failing for 3 days."

tez fit

Train probes, temperatures and gate thresholds for a schema. Needs the fit extra.

--schema FILErequired
Schema YAML file; artefacts go to <dir>/.tez/<name>/.
--labels FILErepeatable
Labelled JSONL rows {"state": …, "labels": {question: label}}.
--data-dir DIRdefault <schema dir>/.tez
Where recorded feedback lives.
--no-feedback
Ignore rows recorded through POST /v1/feedback.
--holdout FRACTIONdefault 0.3
Share of each question's labels held out for calibration.
--min-labels Ndefault 20
Fewest labels for which a probe is trained.
--seed Ndefault 0
Seed for the split and the folds.
--no-letters
Skip the letters readout (no letters calibration, no blend).
--no-blend
Serve the probe alone, without the zero-shot letters prior.

tez suggest

Pick the most typical unlabelled states to label first. Needs the fit extra and an embedding backend.

--schema FILErequired
Schema YAML file.
--unlabelled FILErequired
JSONL rows with a state, or one state per line.
--n Ndefault 25
How many rows to pick.
--question ID
Cluster on one question's prompt (default: all questions averaged).
--seed Ndefault 0
Seed for the clustering.
--out FILE
Write the picks here (JSONL with empty labels) instead of stdout.

tez eval

Accuracy and calibration (ECE) per question on labelled rows.

--schema FILErequired
Schema YAML file.
--labels FILErequired, repeatable
Labelled JSONL rows.
--readout {auto,letters,probe}default auto
Which readout to evaluate.
--alpha ALPHA
Also report the gate: share acted and error among acted.
--include-seen
Keep rows a probe was trained on.
--json FILE
Also write the results as JSON.

tez truncate

Keep the first N transformer blocks of a GGUF. Needs the truncate extra.

usage
tez truncate SRC N DST
SRC
Input .gguf.
N
Blocks to keep.
DST
Output .gguf; it must differ from the input.

Python API

The server is a thin layer over the Tez class, and the same engine runs in your own process. decide returns the wire-format response as a dict.

python
from tez import Tez

tez = Tez(backend="http://127.0.0.1:8091", template="gemma4")
res = tez.decide(
    "Help! My payouts have been failing for 3 days.",
    questions={
        "topic": {
            "type": "choice",
            "instructions": "What is the message about?",
            "criteria": {"billing": "Payments, payouts, invoices", "technical": "Something is broken", "sales": None},
        },
    },
)
print(res["answers"]["topic"])      # the same shape as the HTTP response

# with schemas, probes and a gate
tez = Tez(backend="http://127.0.0.1:8091", template="gemma4",
          embed_backend="http://127.0.0.1:8092", embed_template="qwen3", schemas="schemas")
res = tez.decide("I can't log in since this morning.", schema="support-triage", alpha=0.05)
print(res["tez"]["questions"])      # readout, act or escalate, p_correct, calibration_id

Tez(…)

backenddefault http://127.0.0.1:8080
llama-server URL, "fake", or a Backend instance.
templatedefault "gemma4"
Prompt template of the letters model: gemma4 or qwen3.
schemas
A directory of *.yaml schemas, a schema file, Schema objects, or a list of these.
embed_backend, embed_template
A separate server for probe features and its template (default: the letters backend and template).
cache_promptdefault True
llama.cpp prompt caching; switched off automatically for Qwen3.5 model names.
data_dir
Where feedback is written (default <schema dir>/.tez).
model_name, embed_model_name
Override the model names read from the servers.

Methods

decide(state, questions=None, schema=None, readout="auto", abstain=False, alpha=None, gate=None, model="tez-latest")
Decide one state. schema is a loaded name or a Schema; gate=False turns a schema's default gate off. Returns the response dict.
handle(body)
Validate and decide a wire-format request body, exactly as the server does.
add_schemas(source)
Load more schemas and their fitted artefacts; returns the names added.
health(), models(), schema_summaries(), schema_detail(name)
The bodies of /healthz, /v1/models, /v1/schemas and /v1/schemas/{name}.
record_feedback(body)
What POST /v1/feedback does: append a corrected label.

Errors are TezError subclasses carrying the HTTP status and type: InvalidRequest (422), BackendRequestError (422) and BackendUnavailable (503). The package also exports load_schema, load_schemas, Schema, Question, parse_question, LlamaCppBackend and FakeBackend. Fitting is in tez.fit (fit, suggest, evaluate), and tez.server.create_app(tez, api_key=None, cors=True) returns the FastAPI application if you want to mount it in your own server.

Troubleshooting

llama-server crashes on a Qwen3.5 model

Partial reuse of a cached prompt crashes llama.cpp b11100 with hybrid Qwen3.5 GGUFs. Tez switches caching off for backends whose model name matches Qwen3.5; if your file is named otherwise, pass --no-cache-prompt (or --model-name), and send "cache_prompt": false yourself when you call llama-server directly.

Every request re-reads the whole prompt

Start Gemma with --swa-full. Without it the sliding-window cache cannot be rolled back to the shared prefix and each call pays for the full prompt: 205 ms instead of 30 ms per streamed word in the voice loop. Check timings.prompt_n in a /completion response.

No token probabilities from a depth-pruned model

A cut model sometimes puts end-of-sequence first when read greedily, and /completion then returns no completion_probabilities. Tez repeats the request with "ignore_eos": true; do the same when you call llama-server yourself.

503 backend_unavailable

Tez could not reach the model server, or the server is still loading (llama-server answers 503 while it loads, and Tez retries twice). GET /healthz reports backend_status: "unreachable" when nothing answers at --backend.

The playground cannot reach my server

The playground runs in your browser and calls http://127.0.0.1:8787 directly, so the request never leaves your machine. Start tez serve without --no-cors. The first time a public page calls your machine, Chrome asks whether the site may connect to devices on your local network: allow it for this site. Tez answers the browser's private-network preflight with Access-Control-Allow-Private-Network: true by default. A server started with --api-key rejects requests that do not send the key.

A fitted probe is not used

Fits are tied to the question's prompt and to the model. After editing instructions, options, examples or the template, or serving another model, GET /v1/schemas/{name} shows "probe": "stale" with a note, and the question falls back to uncalibrated letters. Run tez fit again.

Flat or wrong letters with your own prompts

Gemma 4 is a thinking model: unless the prompt ends with an empty thought channel, its first token is a channel marker, not an option letter. Tez's gemma4 template ends with <|turn>model, <|channel>thought, <channel|>; use the template that matches the model behind --backend.

Stopping llama-server on Windows

taskkill /IM llama-server.exe silently fails under Git Bash, which rewrites /IM as a path. Use PowerShell, Stop-Process -Name llama-server, and check /props before the next run.

FAQ

Is Tez Jev?

No. Tez is not affiliated with TypeSafe AI. It speaks the same wire format, so clients written for Jev work with it, but it is built from the published technique (reading a decision from one forward pass of an open model), and nothing in it was trained on or derived from Jev's outputs; Jev's terms forbid that. Jev was never run for any number on this site: its figures are third-party published and labelled as such.

What hardware do I need?

Every number here comes from one RTX 5080 laptop GPU with 16 GB, running llama.cpp b11100. Gemma 4 12B at Q8_0 is the default for zero-shot letters; the cut Qwen3.5-4B for probes is a 3.53 GB file. Other GPUs, CPUs and Apple silicon can run llama.cpp, but they have not been measured here.

What are the licences?

Tez's code is MIT. The Gemma 4 and Qwen3.5 weights are Apache-2.0. The SemIf fixtures and prompt code vendored in data/semif/ are MIT. This site's fonts (Geist) are under the SIL Open Font License 1.1 and its icons (Lucide) under the ISC licence; see assets/LICENSES.md.

Does Tez generate text?

No. Each question is one forward pass, and the answer is read from the next-token distribution (letters) or from a hidden state (probe). usage.output_tokens is always 0.

Can I try the API without a model?

tez serve --backend fake runs an offline stand-in that answers from keyword overlap. It is not a model and its answers mean nothing; it exists for wiring clients and tests.

Is Tez on PyPI, a hosted service or the JevBench leaderboard?

None of the three. Install it from GitHub; it runs on your machine and there is no hosted version. Tez has not been submitted to JevBench, so it holds no rank there; the public-tier scores on the benchmarks page use the leaderboard's formulas and are indicative only.
