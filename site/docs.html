Documentation

Run Tez on your own machine and call it like Jev: start llama.cpp with a GGUF model, put tez serve in front of it, and send typed questions to /v1/systemone. The commands here are the ones behind the published numbers.

tez 0.1.0llama.cpp b11100Python 3.10+MIT

Quickstart

Four steps from nothing to a decision. They assume a GPU that can hold Gemma 4 12B at Q8_0; every number on this site was measured on an RTX 5080 laptop GPU with 16 GB. Other GPUs and CPUs run llama.cpp too, but have not been measured here.

  1. Get llama.cpp b11100 and the model

    Download the build for your platform from the b11100 release page, then the weights:

    bash
    hf download unsloth/gemma-4-12b-it-GGUF gemma-4-12b-it-Q8_0.gguf --local-dir .

  2. Start llama-server with the measured flags

    bash
    llama-server -m gemma-4-12b-it-Q8_0.gguf -ngl 99 -c 4096 -b 512 --port 8091 --host 127.0.0.1 -np 1 --no-webui --swa-full

  3. Install Tez and start it in front of the model

    bash
    pip install git+https://github.com/Jibalmi/Tez
tez serve --backend http://127.0.0.1:8091 --template gemma4

  4. Ask a question

    bash
    curl -s http://127.0.0.1:8787/v1/systemone \
  -H "Content-Type: application/json" \
  -d '{"state": "Help! My payouts have been failing for 3 days.",
       "questions": {"topic": {"type": "choice",
         "instructions": "What is the message about?",
         "criteria": {"billing": "Payments, payouts, invoices",
                      "technical": "Something is broken", "sales": null}}}}'

    The answer comes back in Jev's wire format: the chosen option, a probability for every option and a confidence. Nothing is generated, so usage.output_tokens is always 0. Windows users can send the same request from PowerShell: see First request.

No model yet? tez serve --backend fake starts an offline stand-in so you can wire up a client. It answers from keyword overlap; it is not a model and its answers mean nothing.

Install

Three pieces run on your machine: llama.cpp's llama-server hosts the model, a GGUF file holds the weights, and Tez reads each decision out of the server's next-token distribution or hidden state.

llama.cpp

Every number on this site was measured with llama.cpp release b11100, the Windows win-cuda-13.4 build. Download the build for your platform and put llama-server on your PATH. Other builds may work; they have not been measured.

Use the official release binaries. Tez talks to llama-server over HTTP and needs no Python bindings; the prebuilt llama-cpp-python wheels we tried were compiled with AVX-512 and crashed on a CPU without it.

Run llama-server

This is the exact command behind the Gemma numbers on this site:

bash
llama-server -m gemma-4-12b-it-Q8_0.gguf -ngl 99 -c 4096 -b 512 --port 8091 --host 127.0.0.1 -np 1 --no-webui --swa-full
-m gemma-4-12b-it-Q8_0.gguf
The model file.
-ngl 99
Offload every layer to the GPU.
-c 4096
Context window in tokens: the prompt, including the state, must fit. Raise it for long states; the JevBench hard tier ran with 8k.
-b 512
Batch size for prompt evaluation.
--port 8091 --host 127.0.0.1
Listen on this machine only.
-np 1
One slot, so the cached prompt prefix lives in one place.
--no-webui
No chat interface.
--swa-full
Keep the full sliding-window cache, so Gemma can reuse the cached options prefix (below).

Add --embeddings --pooling last only when the same server also serves embeddings for probes. Before trusting any number, check which file the server loaded: model_path in curl http://127.0.0.1:8091/props. Our harness asserts it before every run, after a stale server once answered for the wrong model.

Why --swa-full matters

Tez puts the constant part of every prompt first (instructions and options) and the state last, so the server can reuse the cached prefix and evaluate only the new tokens. Gemma uses sliding-window attention, and llama.cpp can only roll that cache back to a shared prefix when the full cache is kept. Without --swa-full the server silently re-evaluates the whole prompt on every request: in the voice loop that was 205 ms per streamed word, with --swa-full 30 ms (11 tokens evaluated per word instead of 394).

To confirm reuse, send two requests that share a prefix to llama-server's /completion and read timings.prompt_n in the second response: it should count only the new tokens.

The probe server

Probes read the hidden state of Qwen3.5-4B cut to 24 of its 32 blocks. Run it as a second server:

bash
llama-server -m Qwen3.5-4B-Q8_0-L24.gguf -ngl 99 -c 4096 --port 8092 --embeddings --pooling last

Prompt caching must stay off for this hybrid model on llama.cpp b11100: reusing part of a cached prompt crashes the server. Tez switches caching off by itself for any backend whose model name matches Qwen3.5, and logs a warning. tez serve --no-cache-prompt forces it off for every backend, including a Gemma letters server, which then loses its cached prefix.

The measured probe runs also passed -b 512 -np 1 --host 127.0.0.1 --no-webui. On the RTX 5080 laptop GPU a probe on this file decides in 58 ms (p50) at 0.793 accuracy on typed-decisions; see latency and depth-pruned models.

Start Tez

bash
tez serve --backend http://127.0.0.1:8091 --template gemma4
output
tez 0.1.0 on http://127.0.0.1:8787  backend http://127.0.0.1:8091 (gemma4), 0 schema(s), 0 probe(s)

Tez listens on http://127.0.0.1:8787. --template must match the model behind --backend: gemma4 for Gemma 4, qwen3 for Qwen3 and Qwen3.5. Without --backend, Tez uses the TEZ_BACKEND environment variable or llama-server's own default address, http://127.0.0.1:8080.

With schemas and the probe server:

bash
tez serve --backend http://127.0.0.1:8091 --template gemma4 \
  --embed-backend http://127.0.0.1:8092 --embed-template qwen3 \
  --schemas schemas

--schemas loads every *.yaml in the directory, with the probes and calibrations tez fit wrote next to them. GET /healthz shows what was loaded. When other machines can reach the server, require a key with --api-key (or TEZ_API_KEY).

API

Tez speaks TypeSafe's /v1/systemone wire format, so a client written for Jev's wire format, JevBench's own runner included, can point its base URL at a Tez server. Everything Tez adds lives in optional fields that strict clients ignore.

Base URL and authentication

Default address: http://127.0.0.1:8787. Without --api-key any Authorization: Bearer <token> is accepted and none is required. With --api-key, every endpoint except /healthz needs Authorization: Bearer <key> or an x-api-key header. CORS is open by default (--no-cors turns it off), and preflights answer Access-Control-Allow-Private-Network: true, so a web page, such as this site's playground, can call a server on your machine.

MethodPathPurpose
POST/v1/systemoneDecide: one state, many typed questions (Jev-compatible)
GET/v1/modelsList model aliases (Jev-compatible)
GET/healthzLiveness, backend and readout status
GET/v1/schemasTez: schemas loaded from --schemas
GET/v1/schemas/{name}Tez: one schema (questions, probe status, calibration)
POST/v1/feedbackTez: record a correct label for a past decision (feeds tez fit)

Answer shapes

The three answer shapes are exactly Jev's:

TypeFieldsMeaning
noulnoulP(yes). No confidence: Jev's noul answers carry none.
choicechoice, probabilities, confidenceThe argmax label, a probability per label (they sum to 1), and confidence = (k·pmax − 1)/(k − 1) for k options: 0 when uniform, 1 when certain.
scorescore, legend, probabilities, confidenceThe expected level Σ i·pi, the level descriptions keyed by level string, a probability per level string, and confidence as for choice.

With tez.abstain, a choice answer can be __none__, with its own probability.

The tez block

latency_ms, and per question the readout used, a decision when a gate applies, and p_correct with calibration_id when a fitted calibration exists.

  • The gate never acts without evidence: act always comes with p_correct and calibration_id. A question with no usable fitted calibration, and any __none__ answer, gets escalate whenever a gate is requested.
  • tez.gate: null or false turns a schema's default gate off; tez.gate: {} uses the schema's default alpha.
  • Thresholds are precomputed for alpha 0.01, 0.02, 0.05, 0.1, 0.15, 0.2, 0.25, 0.3 and the schema's default; any other alpha uses the largest precomputed value at or below it.
  • tez.readout: "probe" is strict: the request fails with 422 if a requested question has no usable probe. auto falls back to letters question by question.
  • A fit is used only while the question's prompt (instructions, options, few-shot examples, template) and the model still match what tez fit saw. Otherwise the question falls back to uncalibrated letters and GET /v1/schemas/{name} marks it stale.

Schemas

A schema is a named, reusable set of questions plus what Tez has learned about them. Put schema files in a directory, start the server with --schemas <dir>, and a request can name the schema instead of repeating its questions.

yaml · schemas/support-triage.yaml
name: support-triage
description: Route and prioritise inbound customer messages.
state: "One customer message (text)."
questions:
  topic:
    type: choice
    instructions: What is the message about?
    criteria:
      billing: Payments, payouts, invoices, refunds
      technical: Something is broken or not working
      account: Login, profile, settings
      sales: Pricing, plans, buying more
  is_urgent:
    type: noul
    instructions: Does this convey urgency?
    criteria:
      "true": Explicitly time-sensitive or blocking
      "false": No urgency expressed
  anger:
    type: score
    instructions: How upset is the writer?
    criteria: [Calm, Frustrated, Very angry]
gate:
  alpha: 0.05          # optional default for tez.gate
examples:              # optional labelled rows: the first 4 per question become few-shot examples
  - state: "I was charged twice this month."
    labels: {topic: billing, is_urgent: "false", anger: 1}

A request that names the schema needs only the state:

json · request
{"state": "I was charged twice this month.", "schema": "support-triage"}

Fields

FieldDescription
nameLetters, digits, ., _ or -; defaults to the file name. Names must be unique across the directory.
descriptionFree text for people and for GET /v1/schemas.
stateWhat a state is, for people. It is not sent to the model.
questionsMap of question id to question, in the wire format's shape.
gate.alphaOptional default gate for every request that names the schema. A request turns it off with "gate": null or false.

Tez reads YAML with 1.2 booleans: only true and false are booleans, so options called yes, no, on or off stay text. Worked examples in the cached prefix are measured free accuracy: four examples of the same question took the 12B from 0.704 to 0.725 on typed-decisions, with no training.

Trained artefacts

tez fit writes what it learns next to the schema, in schemas/.tez/<name>/:

  • probes.npz: per-question logistic weights on the embedding backend's features.
  • calibration.json: per question, the temperature of each readout and the conformal thresholds per alpha, with the prompt fingerprint they were fitted on.
  • manifest.json: backend, template, model, layer or cut, label counts, settings and date.

Feedback from POST /v1/feedback goes to <data-dir>/feedback/<schema>.jsonl. Editing a question's instructions, options, examples or template, or serving a different model, makes its fit stale: the question falls back to uncalibrated letters until you run tez fit again.

Readouts

A readout turns one forward pass into a probability per option. Choose one per request with tez.readout; auto uses a probe where one is trained and current, and letters otherwise.

ReadoutNeedsBackend callMeasured, typed-decisions
lettersNothing (zero-shot)/completion, one token, top-200 log-probabilities0.704 (Gemma 4 12B Q8_0)
probe25 to 50 labels per question (tez fit)/embedding (last-token state)0.793 (Qwen3.5-4B cut to 24 blocks)
blendA few labelsBoth0.766 (12B letters + 50 typical labels per question)

Letters

The prompt gives the instructions, then the options, each with a letter, then the state, and ends where the model would answer. One /completion call reads the top-200 log-probabilities of the next token; the softmax over the option letters is the distribution, divided by a per-question temperature once tez fit has calibrated it. More than 26 options run as a chunked tournament: chunks of 20 options plus "none of the options above fits", then the chunk winners meet in a final. Raw letters are poorly calibrated: ECE 0.262 on typed-decisions before a temperature, 0.067 after one.

Probe

One /embedding call returns the last-token state of the same prompt, and a per-question logistic probe trained by tez fit maps it to option probabilities. tez fit trains a probe once a question has 20 labels; the measurements say 25 to 50 per question is where a probe starts to pay. A logistic probe is fitted with a proper scoring rule, so it comes out calibrated: ECE 0.023 as read on typed-decisions.

Blend

Unless you fit with --no-blend, a probe is served blended with the zero-shot letters: weight n/(n + 10) on a probe trained on n labels and the rest on the letters, so with few labels the zero-shot prior still counts. Fifty typical labels per question on top of the 12B's zero-shot answers reach 0.766, the level of Laya's checkpoint fine-tuned on the whole train split.

With tez.abstain, the probability of __none__ comes from the letters readout even when a probe answers. Accuracy by question type and calibration for each readout are on the benchmarks page.

Fit a schema

Zero-shot letters need no labels. With labels, tez fit calibrates every question, trains probes and precomputes the gate's thresholds. The loop below is the one the measurements favour: label the most typical rows first, and keep the zero-shot answers as a prior. The examples use both servers from Run llama-server.

  1. Write the schema

    See Schemas. Save it as schemas/support-triage.yaml.

  2. Pick the rows to label

    bash
    tez suggest --schema schemas/support-triage.yaml --unlabelled inbox.jsonl --n 50 --out to-label.jsonl \
  --backend http://127.0.0.1:8091 --template gemma4 \
  --embed-backend http://127.0.0.1:8092 --embed-template qwen3

    inbox.jsonl holds unlabelled states: JSON rows with a state field, or one plain-text state per line. tez suggest embeds each state with every question's prompt, clusters the states (k-means on 32 principal components) and returns the member nearest each centre, largest cluster first.

  3. Label them

    Fill in labels on each row: an option key for a choice question, true or false for a yes/no question, the level index for a score question.

    jsonl · to-label.jsonl
    {"state": "I was charged twice this month.", "labels": {"topic": "billing", "is_urgent": "false", "anger": 1}}

  4. Fit

    bash
    tez fit --schema schemas/support-triage.yaml --labels to-label.jsonl \
  --backend http://127.0.0.1:8091 --template gemma4 \
  --embed-backend http://127.0.0.1:8092 --embed-template qwen3

    For each question, tez fit splits the labelled rows once (30 % held out, --holdout), fits a temperature for the letters, trains a logistic probe once the question has 20 labels (--min-labels) and blends it with the letters. The held-out rows are used for nothing but measurement and the gate's thresholds, so the error bound rests on decisions nothing was fitted on. It prints a table (labels, probe status, held-out accuracy of each readout, temperatures, the confidence cut at alpha 0.05) and writes schemas/.tez/support-triage/.

  5. Evaluate on rows it has not seen

    bash
    tez eval --schema schemas/support-triage.yaml --labels held-out.jsonl --alpha 0.05 \
  --backend http://127.0.0.1:8091 --template gemma4 \
  --embed-backend http://127.0.0.1:8092 --embed-template qwen3

    Accuracy, ECE and mean confidence per question, and with --alpha the share of decisions acted on and the error among them. Rows a probe was trained on are skipped unless you pass --include-seen.

  6. Serve it, and keep learning

    Restart tez serve with --schemas schemas: requests that name the schema use its probes and calibration. When a person corrects a decision, send the right label to POST /v1/feedback; the next tez fit reads those rows too (--no-feedback ignores them).

What the measurements say about labels (typed-decisions, probe on layer 26 of the frozen Qwen3.5-4B, 3 seeds): random rows reach 0.707 with 25 labels per question and 0.741 with 50; the most typical rows first reach 0.734 with 25; typical rows on top of the 12B's zero-shot answers reach 0.766 with 50. The 12B alone scores 0.705 with no labels. See the chart.

The gate

Ask for a gate and every answer also says act or escalate. The gate is conformal selection (Jin and Candès, 2023): it chooses which decisions to act on so that the expected share of wrong ones among them stays at or below a target alpha.

json · request
{"state": "I can't log in since this morning.", "schema": "support-triage", "tez": {"gate": {"alpha": 0.05}}}

The same gate is gate: {alpha: 0.05} in a schema, --alpha 0.05 on tez decide, or alpha=0.05 in Python.

How it decides

For a decision with confidence c, the conformal p-value of "this decision is wrong" counts the held-out calibration decisions that were wrong with confidence at least c: (1 + that count) / (number of calibration decisions + 1). Benjamini–Hochberg at level alpha over the held-out decisions gives one confidence cut per question and alpha, which tez fit stores. At request time Tez acts when the answer's top probability reaches the cut, and escalates otherwise.

What it guarantees, and what it needs

  • A bound on the expected error rate among acted decisions, when live traffic resembles the held-out rows. It does not bound any single batch, and it does not survive a shift in traffic or an edited question: fit again when either changes.
  • A fitted calibration. A question without one, and any __none__ answer, always escalates when a gate is requested.
  • A conservative alpha. Thresholds exist for alpha 0.01, 0.02, 0.05, 0.1, 0.15, 0.2, 0.25, 0.3 and the schema's default; a value in between uses the largest one below it.

Measured on typed-decisions, over 50 random calibration splits: at a 5 % bound a probe acts on 40 % of decisions with a realised error of 5.2 %, and the 12B's zero-shot letters act on 24 % at the same realised error. What escalate means is yours to choose: a person, a larger model, or another question. The cold-start measurements favour also sending a small random slice of acted decisions to people, so the labels you collect are not only the hard cases. See the chart.

Streaming and voice

Tez was built and measured on a voice loop: 220 spoken commands over 16 actions, decided word by word as the transcript grows. Three things make it fast and safe.

  • Options cached, message last. The action list is the constant prefix and the transcript is the only new text per word. With --swa-full the 12B spends 30 ms of compute per streamed word (45 ms round trip), evaluating 11 tokens where the transcript-first layout needs 358.
  • Re-decide on every word. Send the partial transcript as the state each time a word arrives; the cached prefix keeps each call cheap.
  • A confident none on a partial transcript means keep listening. Early in a sentence the right answer is often "none of these yet". Read it as "wait for more words", never as "do nothing".

Actions then fire by class: a cheap, reversible action such as opening an app fires on one confident partial; media and play actions need the same answer on two consecutive partials; typing and closing wait for the end of the utterance. Measured: 1 harmful action in 198 utterances, the first action on average at word 3.6 of 5.4, and Notepad open 652 ms into "open notes and type hello world", 1.3 s before the speaker finished.

The policy lives in your client; Tez answers each partial. A sketch with part of the measured action set:

python
from tez import Tez

tez = Tez(backend="http://127.0.0.1:8091", template="gemma4")
ACTION = {
    "type": "choice",
    "instructions": "Which action does the speaker want?",
    "criteria": {
        "open_notes": "Open the notes or notepad application.",
        "type_text": "Type the dictated text into the app that is currently in focus.",
        "play_spotify": "Play a specific song, artist, album or playlist on Spotify.",
        "none": "Out of scope: chit-chat, a question, or a request for something the assistant cannot do.",
    },
}
FIRE_NOW = {"open_notes"}      # cheap and reversible: one confident partial
TWICE = {"play_spotify"}       # the same answer on two consecutive partials
AT_END = {"type_text"}         # needs the whole utterance


def on_words(transcript, seen, final=False):
    """Call on every ASR partial; returns an action to run, or None to keep listening."""
    answer = tez.decide(transcript, questions={"action": ACTION})["answers"]["action"]
    choice = answer["choice"]
    seen.append(choice)
    if choice == "none" or answer["probabilities"][choice] < 0.9:
        return None            # a confident none on a partial means keep listening
    if choice in AT_END and not final:
        return None
    if choice in TWICE and seen[-2:] != [choice, choice]:
        return None
    return choice

The measured policy is experiments/stream_policy.py, and the whole loop with speech recognition is experiments/voice_demo.py. Out-of-scope speech that starts like a command ("youtube is down again") is the remaining risk: it is a property of language, handled by firing cheap actions first.

Python API

The server is a thin layer over the Tez class, and the same engine runs in your own process. decide returns the wire-format response as a dict.

    "Help! My payouts have been failing for 3 days.",
    questions={
        "topic": {
            "type": "choice",
            "instructions": "What is the message about?",
            "criteria": {"billing": "Payments, payouts, invoices", "technical": "Something is broken", "sales": None},

)
print(res["answers"]["topic"])      # the same shape as the HTTP response

# with schemas, probes and a gate

          embed_backend="http://127.0.0.1:8092", embed_template="qwen3", schemas="schemas")

Troubleshooting

llama-server crashes on a Qwen3.5 model

Partial reuse of a cached prompt crashes llama.cpp b11100 with hybrid Qwen3.5 GGUFs. Tez switches caching off for backends whose model name matches Qwen3.5; if your file is named otherwise, pass --no-cache-prompt (or --model-name), and send "cache_prompt": false yourself when you call llama-server directly.

Every request re-reads the whole prompt

Start Gemma with --swa-full. Without it the sliding-window cache cannot be rolled back to the shared prefix and each call pays for the full prompt: 205 ms instead of 30 ms per streamed word in the voice loop. Check timings.prompt_n in a /completion response.

No token probabilities from a depth-pruned model

A cut model sometimes puts end-of-sequence first when read greedily, and /completion then returns no completion_probabilities. Tez repeats the request with "ignore_eos": true; do the same when you call llama-server yourself.

503 backend_unavailable

Tez could not reach the model server, or the server is still loading (llama-server answers 503 while it loads, and Tez retries twice). GET /healthz reports backend_status: "unreachable" when nothing answers at --backend.

The playground cannot reach my server

The playground runs in your browser and calls http://127.0.0.1:8787 directly, so the request never leaves your machine. Start tez serve without --no-cors. The first time a public page calls your machine, Chrome asks whether the site may connect to devices on your local network: allow it for this site. Tez answers the browser's private-network preflight with Access-Control-Allow-Private-Network: true by default. A server started with --api-key rejects requests that do not send the key.

A fitted probe is not used

Fits are tied to the question's prompt and to the model. After editing instructions, options, examples or the template, or serving another model, GET /v1/schemas/{name} shows "probe": "stale" with a note, and the question falls back to uncalibrated letters. Run tez fit again.

Flat or wrong letters with your own prompts

Gemma 4 is a thinking model: unless the prompt ends with an empty thought channel, its first token is a channel marker, not an option letter. Tez's gemma4 template ends with <|turn>model, <|channel>thought, <channel|>; use the template that matches the model behind --backend.

Stopping llama-server on Windows

taskkill /IM llama-server.exe silently fails under Git Bash, which rewrites /IM as a path. Use PowerShell, Stop-Process -Name llama-server, and check /props before the next run.

FAQ

Is Tez Jev?

No. Tez is not affiliated with TypeSafe AI. It speaks the same wire format, so clients written for Jev work with it, but it is built from the published technique (reading a decision from one forward pass of an open model), and nothing in it was trained on or derived from Jev's outputs; Jev's terms forbid that. Jev was never run for any number on this site: its figures are third-party published and labelled as such.

What hardware do I need?

Every number here comes from one RTX 5080 laptop GPU with 16 GB, running llama.cpp b11100. Gemma 4 12B at Q8_0 is the default for zero-shot letters; the cut Qwen3.5-4B for probes is a 3.53 GB file. Other GPUs, CPUs and Apple silicon can run llama.cpp, but they have not been measured here.

What are the licences?

Tez's code is MIT. The Gemma 4 and Qwen3.5 weights are Apache-2.0. The SemIf fixtures and prompt code vendored in data/semif/ are MIT. This site's fonts (Geist) are under the SIL Open Font License 1.1 and its icons (Lucide) under the ISC licence; see assets/LICENSES.md.

Does Tez generate text?

No. Each question is one forward pass, and the answer is read from the next-token distribution (letters) or from a hidden state (probe). usage.output_tokens is always 0.

Can I try the API without a model?

tez serve --backend fake runs an offline stand-in that answers from keyword overlap. It is not a model and its answers mean nothing; it exists for wiring clients and tests.

Is Tez on PyPI, a hosted service or the JevBench leaderboard?

None of the three. Install it from GitHub; it runs on your machine and there is no hosted version. Tez has not been submitted to JevBench, so it holds no rank there; the public-tier scores on the benchmarks page use the leaderboard's formulas and are indicative only.
